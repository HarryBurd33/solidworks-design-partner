## Actionable initial findings

1. **C1 response gap — conditional material recommendation.** The actual response asks one useful envelope question and proposes an accessible two-piece enclosure, but it only says material depends on conditions. The frozen case expects conditional material/lid recommendations. Add a concrete bounded material proposal with its reason and the conditions that could change it, without turning that into a new interview. This is an observable response failure, not an invented measurement or critical failure. Initial grade: 1/2.

2. **C11 response gap — manual continuation.** The response correctly blocks blind retry, preserves the existing file, calls for process/document/file reconciliation, retains diagnostics and uses a fresh filename. It does not give the manual fallback expected by the case. Add the specific next safe manual stage after reconciliation—for example, inspect the intended closed profile and manually create the requested boss extrusion in a preserved copy—without bypassing the unknown-running-process check. Initial grade: 1/2.

3. **Macro path bug — initial `SmokePlate.bas` lines 37–38.** For an absolute root output such as `C:\plate.SLDPRT`, `Left$(OUTPUT_PATH, InStrRev(OUTPUT_PATH, "\\") - 1)` produces `C:` instead of `C:\`. That is a drive-relative pathname, so the parent preflight inspects the wrong object and can reject a valid destination or establish the wrong folder fact. `PathExists` also accepts files as well as directories. Preserve the root separator and test that the parent is actually a directory, including ordinary nested paths, drive roots and UNC paths. This finding is from the initially inspected source with SHA-256 `fac0a3e40d5aeb2028ba68f54807ef50ee010006e55d98109ff76c499d9f6252`; it does not claim a Windows reproduction. The parent reports a repair was applied during review. This report preserves the initial finding; repaired source is not accepted until separately rechecked.

4. **Diagnostic maintainability — initial macro lines 111–113.** The success dialog hard-codes `80 x 40 x 3 mm`, while the guide permits editing source dimension constants before an independent run. It can direct the user to verify stale dimensions after a legitimate change. Build that message from the constants or explicitly restrict this source to the unchanged smoke test. This is a minor defect, not a fabricated model-dimension check: the dialog already tells users to inspect geometry independently.
